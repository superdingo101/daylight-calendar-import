# v0.9.0 — Daylight Calendar Import

This release brings the public-beta improvements into the stable self-hosted Home Assistant integration. Import event announcements using your existing AI Task provider, review the proposed events, and explicitly approve what goes onto your calendars. No Daylight Cloud account or subscription is required.

## Highlights

- **Import with less effort.** Select **New import** from the Daylight Imports header, paste an announcement or upload a JPEG, PNG, WebP or PDF, and review one or more extracted events. Optional Direct IMAP continues to support email and attachment intake. [#172](https://github.com/superdingo101/daylight-calendar-import/pull/172)
- **A clearer review inbox.** Sources group their extracted events in a compact review flow, with streamlined event cards, compact actions, and visible destination calendars. Every calendar write still requires your approval. [#190](https://github.com/superdingo101/daylight-calendar-import/pull/190), [#191](https://github.com/superdingo101/daylight-calendar-import/pull/191), [#196](https://github.com/superdingo101/daylight-calendar-import/pull/196)
- **Better calendar safety.** Conflict review shows existing event and overlap times and checks configured observation calendars before approval confirmation. Observations can be incomplete and are advisory; exact-duplicate and permission safeguards remain in force. [#167](https://github.com/superdingo101/daylight-calendar-import/pull/167), [#168](https://github.com/superdingo101/daylight-calendar-import/pull/168)
- **Handle uncertain inputs conservatively.** Recurring announcements are flagged rather than silently reduced to a single event. Imported source material is treated as untrusted AI evidence, and source-text and routing-alias submissions are bounded. [#166](https://github.com/superdingo101/daylight-calendar-import/pull/166), [#169](https://github.com/superdingo101/daylight-calendar-import/pull/169), [#170](https://github.com/superdingo101/daylight-calendar-import/pull/170)
- **More useful activity and recovery.** Permanently failed notification deliveries are visible in Recent activity. Uncertain calendar writes remain subject to explicit review rather than automatic retries. [#171](https://github.com/superdingo101/daylight-calendar-import/pull/171)

## Important fixes from beta testing

- Correct inferred UTC offsets across daylight-saving transitions, and reject nonexistent wall-clock times explicitly associated with named IANA time zones before they can be approved. [#175](https://github.com/superdingo101/daylight-calendar-import/pull/175), [#241](https://github.com/superdingo101/daylight-calendar-import/pull/241)
- Fix image/PDF uploads with unsafe filenames and avoid repeating the same validation guidance for unsupported or oversized files. [#189](https://github.com/superdingo101/daylight-calendar-import/pull/189), [#245](https://github.com/superdingo101/daylight-calendar-import/pull/245)
- Allow deliberate re-import of a duplicate manual submission for review, without automatically creating a calendar event. [#176](https://github.com/superdingo101/daylight-calendar-import/pull/176)
- Keep the Daylight Imports panel registered during settings-triggered integration reloads so saving settings does not unexpectedly return to the Home Assistant dashboard. [#239](https://github.com/superdingo101/daylight-calendar-import/pull/239)
- Detect conflicting updates from stale Routing tabs instead of silently overwriting aliases saved in another tab. Review the current aliases and explicitly confirm any intended replacement. [#240](https://github.com/superdingo101/daylight-calendar-import/pull/240)

## Installation and compatibility

Home Assistant **2026.7.4 or newer** is required, along with a configured AI Task entity and at least one allowed, writable calendar. Automated compatibility checks cover Home Assistant **2026.7.4 and 2026.11.0**; that does not certify every intervening or newer release or every AI model. [#216](https://github.com/superdingo101/daylight-calendar-import/pull/216)

Install through HACS on supported older Home Assistant versions or through the built-in Marketplace on Home Assistant 2026.11+. If the integration is not in the default catalog, add this GitHub repository as a custom integration source. See the [installation guide](/installation).

### Upgrading from v0.8.0 or a v0.9.0 beta

1. **Back up Home Assistant** before upgrading, including private Daylight storage.
2. Update the existing integration through HACS/Marketplace and restart Home Assistant when required. **Do not remove and re-add** the existing integration: that can erase pending drafts, history and deduplication fingerprints while leaving previously written calendar events in place.
3. Verify the AI Task entity, allowed/default calendars, routing aliases and pending review queue. Inspect drafts before approving anything. If a calendar write has an uncertain outcome, inspect the destination calendar before choosing a recovery outcome.

For a first installation, follow [Install Daylight Calendar Import](/installation) and then [Quickstart](/quickstart).

## Known limitations

- AI extraction may miss or misinterpret dates, time zones, event counts, locations or meeting details. Review each draft. Images and scanned PDFs require an AI Task provider/model that supports the necessary attachments; text-layer PDFs can work with text-only providers.
- Recurrence detection is best-effort. **Creating recurring events (RRULE), automatically editing or deleting existing calendar events, and automatic approval are not supported.**
- Conflict checks can be incomplete and do not guarantee a conflict-free calendar. Notification delivery is at least once, so notifications may repeat following a crash; uncertain calendar writes are not blindly replayed.
- Direct IMAP uses one dedicated mailbox with password/app-password authentication. Hosted email, billing, SMS/MMS and Daylight Cloud integration are **not** included in this self-hosted release.
